# Домен Авторизация

`src/features/auth/` — вход в админ-панель WebStudio.

## Поток входа
1. `LoginPage` (`/:lang/admin/login`) → форма email + password → `useSignIn`.
2. `useSignIn` вызывает `api.ts` → `supabase.auth.signInWithPassword(...)`.
3. Supabase выдаёт JWT-сессию; `persistSession: true` в [[Точка входа и провайдеры|supabase.ts]] — хранится в localStorage.
4. `ProtectedRoute` проверяет наличие сессии через `useSession` (обёртка над `supabase.auth.getSession`).

## Компоненты и хуки
- `useSession` — отдаёт `{ session, loading }`, реагирует на `onAuthStateChange`.
- `useSignIn` — мутация входа, редиректит на `/admin` после успеха.
- `ProtectedRoute` — HOC-wrapper для всей админ-зоны в [[Маршрутизация]].

## Роли
Единственная роль с правами — `admin` в таблице `profiles`. Проверяется на стороне Supabase функцией `is_admin()` (см. [[Безопасность RLS и CSP]]). ProtectedRoute видит только **наличие сессии**, не роль — RLS не даст залогиненному не-админу читать/писать данные.

## Сессия
- `autoRefreshToken: true` — токен обновляется автоматически.
- `detectSessionInUrl: true` — обрабатывает magic link / OAuth callback (если подключать в будущем).
- При разлогине — `supabase.auth.signOut()`.

## Passkey / WebAuthn
`PasskeyAuth` показывает Passkey как основной способ входа, если браузер
поддерживает `window.PublicKeyCredential`. Запрос к системному аутентификатору
запускается только после клика пользователя.

Поток входа:
1. `supabase.auth.passkey.startAuthentication()` получает одноразовый challenge.
2. Клиент преобразует Base64URL-поля и вызывает `navigator.credentials.get()`.
3. `supabase.auth.passkey.verifyAuthentication(...)` проверяет подписанный ответ и
   сохраняет выданную Supabase-сессию.

После входа по паролю клиент предлагает регистрацию:
1. `supabase.auth.passkey.startRegistration()` получает challenge для текущего пользователя.
2. Клиент вызывает `navigator.credentials.create()`.
3. `supabase.auth.passkey.verifyRegistration(...)` сохраняет публичный ключ,
   счётчик и метаданные аутентификатора на стороне Supabase Auth. `friendly_name`
   автоматически выводится из AAGUID аутентификатора и может быть переименован
   через management API.

Биометрические данные не читаются и не передаются приложению. Face ID, отпечаток
пальца, Windows Hello и PIN-код остаются системным способом разблокировки
приватного ключа на устройстве.

Passkey Auth пока экспериментальный. Нужен `@supabase/supabase-js >= 2.105.0` и
опция `auth.experimental.passkey: true`.

### Настройка окружений
Локальный `supabase/config.toml` настроен для `http://localhost:5173`. В hosted
Supabase нужно включить Authentication → Passkeys и задать стабильный production
RP ID до регистрации первых Passkey:

- RP Display Name: `WebStudio`
- RP ID: bare domain без схемы, порта и пути
- RP Origins: точные production origins по HTTPS

Смена RP ID делает зарегистрированные ранее Passkey непригодными для входа.
